# v0.1.0 release evidence

The first public preview uses tag `v0.1.0`, source commit
`0edc23604e2527829bbafb397fcebd612d860460`.
The [release notes](../../release-notes/v0.1.0.md) cover desktop, CLI and stdio MCP.
Server runtime, sync and Developer ID signing/notarization remain outside this release.

## Source verification

- Preparation [PR #65](https://github.com/LennardZuendorf/shards/pull/65) passed all eight
  [CI jobs](https://github.com/LennardZuendorf/shards/actions/runs/41437661608) before merge.
- Local verification passed 1,707 Rust tests, 763 frontend tests and 46 release/plugin tests,
  plus the frontend build, formatting, whitespace and strict spec validation.
- Publisher repair [PR #66](https://github.com/LennardZuendorf/shards/pull/66) passed all eight
  [CI jobs](https://github.com/LennardZuendorf/shards/actions/runs/41438987779).
  Its 48 release/plugin tests include the observed draft-lookup failure. The full Rust suite
  passed again. A live read resolved the intended draft and matched its committed notes.
- The publisher reads trusted `main`; the repair did not move the release tag or change
  the candidate's application source.

## First tag attempt

[Run 41438356094](https://github.com/LennardZuendorf/shards/actions/runs/41438356094)
passed all source checks and the Linux native build. ARM compilation and signing passed,
then direct image creation failed with `Resource busy`. Intel created its DMG and verified
signatures, bundled tools and native process launch, then artifact upload failed with
`Failed to CreateArtifact: Unable to make request: ENOTFOUND`.

The packaging code and workflow matched the successful prior candidate
[41432455552](https://github.com/LennardZuendorf/shards/actions/runs/41432455552).
One fresh-runner retry retained the exact tag and source. These observations do not establish
the infrastructure failures' causes.

## Verified GitHub publication

Attempt 2 passed all three native targets, assembly and both native Homebrew lifecycle jobs.
Each Brew job reported `homebrew-native-install` and `homebrew-conflict-refusal` for `0.1.0`.
Upgrade testing reported `not-tested-no-previous-candidate`, as no earlier release existed.

[v0.1.0](https://github.com/LennardZuendorf/shards/releases/tag/v0.1.0), release ID `431390027`,
published at `2026-11-02T12:24:39Z`. The seven assets comprise five platform packages,
`release-manifest.json` and `SHA256SUMS`. Independent local verification passed every checksum;
published sizes and SHA256 digests matched all seven candidate files. The published title
and complete notes matched the intended draft.

The subsequent tap push failed with `403 Permission denied` for `HOMEBREW_TAP_TOKEN`.
The GitHub release remained complete. After the owner updated the token, attempt 3 retried
only the publisher, verified and reused all existing assets, and completed successfully.

## Public Homebrew installation

The publisher updated the tap to commit `d4c27b98f1eebfe837540bff6152ec57f82fd699`.
[Verify tap 41445332082](https://github.com/LennardZuendorf/homebrew-tap/actions/runs/41445332082)
passed on `macos-15` and `macos-15-intel`. Both jobs passed Ruby syntax, tap style,
installation and testing of tools from public release URLs, desktop dependency and removal,
and stable metadata audit. The public formula/cask versions and hashes match the manifest.

These public checks verify the CLI version, disposable-vault status, MCP executable presence,
desktop installation and survival of the tools after desktop removal. MCP protocol exchanges
and native app launch were checked in the candidate, not repeated in the public tap workflow.

Native process launch is a startup smoke check, not full native UI acceptance. Minimum
macOS metadata checks do not establish runtime compatibility on macOS 13.3. The server remains
`unavailable` with reason `server_not_implemented`; no server application was published.
