# Shards v0.2.0 — first-run truth, complete task listings and claim takeover

Shards is a task manager for humans and AI agents, backed by Markdown files you own.
v0.2.0 is a delta release over v0.1.0 across the CLI, stdio MCP, the local agent harness and
the desktop preview. The sections below are the release: "What you can do" lists every
user-visible change with the pull request that carries it, and "Merged, not user-facing" names
the product work in the range that changes nothing you can observe. Edits to this document are
not listed; a list that names itself would never close. No pull-request count is stated
here, because the list is the claim.

## What you can do

- **Start from a clean machine in either order.** `shards config set core.vault_path` seeds
  the config when no file exists, so it no longer needs an `init` first; `init` stays the verb
  that creates and attaches a vault. (#74, closes #70, #71)
- **Count what is actually in your vault.** `task list --all` lists every matching task, a
  capped listing says so on stderr (`showing 20 of 25 tasks — use --all`), and `--limit 0` is
  a usage error instead of an empty result. (#75, closes #72)
- **Recover a claim stranded by a dead agent.** `task claim <id> --takeover` and
  `task release <id> --takeover` clear a claim untouched for two days and append the previous
  holder to `## Claim history`; a fresher claim stays protected. `task list` adds
  `claim_recoverable`, `shards status` names the task, and MCP carries the same rule. (#42,
  closing #38, with claim readiness derived under the same lock)
- **Trust the desktop preview's counts and keyboard.** Five verified defects are fixed: a
  failed search shows its error with retry instead of "No results", archived projects' tasks
  leave Today, Upcoming and label views, views refresh on focus when change notifications are
  down, `x` selects rather than completing, and dropping an agent-held card on "To do" asks
  before releasing it. (#57)
- **Describe a task without losing what you typed in it.** The description saves one second after
  typing stops and when you leave the field, so it no longer has a Save button to forget; ⌘Enter
  saves immediately, Escape leaves edit mode writing nothing, and a draft survives switching to
  another task and back. When another writer committed first the save is refused rather than
  overwriting them — the banner names who changed it, with **Use latest** and **Use my
  description**. (#87)
- **Get an error for an explicitly blank relation.** `task new --parent ''` and `--project ''`,
  `memory new --project ''` and `--supersedes ''` exit 2 with a validation message instead of
  silently dropping the value, a bad task id is an id error rather than a filesystem sandbox
  escape, and `memory update --project ''` clears the key. (#42, closes #39)
- **Never pipe help text into `jq` again.** A bare group verb with `--json` (`shards config
  --json`) is a usage error on stderr naming the subcommand that really emits JSON; without
  `--json` the old shape is unchanged. (#85, closes #84)
- **Read parity evidence instead of a summary.** Inbox and duplicate (#73), bulk update with
  one undo, labels on a row and the list/board switch (#80), palette selection and the memory
  and scratch managers (#81), and a project's archive, delete and undo (#86) are pinned by
  tests, as is a child's stderr surviving a closed stdin in the harness (#79, closing #78).

## Merged, not user-facing

- **The release files themselves (#88).** Version bumps across the manifests, this document and the
  upgrade note. No command, flag or file format moved.
- **The spec record was wrong, not the product (#95).** Spec notes were re-stamped, the `have` rule was
  ruled on and appended to the decision log, and the parity rows were made to match evidence that
  already existed. No behaviour changed; the record now says what shipped.
- **The check that could not see what it enforced (#96, #103).** The quality job checked out a depth-1
  clone, so the spec validator skipped its freshness rule entirely and `main` stayed green while a full
  clone reported errors. The checkout now fetches full history and pins the corrected validator; #103
  moves that pin from the fix's branch head to its merge commit, same tree. Nothing user-visible — what
  changed is that the check now fails when it should.
- **#82 — `main` went red and is green again.** A CLI test still asserted the old bare-array
  `task list --json` shape after the `{tasks, total}` envelope landed, and a spec note had
  grown past its line budget. Both were repaired; no command, flag or file format moved.

## Breaking change for scripts

`task list --json` returns `{"tasks": [...], "total": N}` instead of a bare array. `total` is
the full match count after every filter and independent of any limit, so
`total > (.tasks | length)` means the listing was truncated. Replace `jq '.[]'` with
`jq '.tasks[]'`, and `jq length` with `jq '.tasks | length'` for the rows returned (`jq length`
on the envelope is `2`, its key count). Read `.total` on its own when you want the match count
rather than the page — with 25 matches, `--limit 5` returns 5 rows and `total` 25. The `note`,
`memory`, `scratch` and `asset` lists still return arrays. (#75)

## Upgrading

Nothing in this release changes the vault format, the config schema or the frontmatter keys,
so upgrading from 0.1.0 is a binary swap. `shards --version` prints `0.2.0` — the thing that
tells this build apart from 0.1.0, which has no `--all`, caps a bare `task list` at 20
silently, returns bare arrays from `--json` lists, and needs a config before `config set`.

## Truth limits

- The private remote MCP is **loopback-executed, deployment unproven** (#69): the merged source
  from #64 ran end to end on loopback against a throwaway vault, with no Tailscale, DNS or
  public listener. The 39-tool allowlist has run against a throwaway vault only (17 of the 39
  entries answered one `notes:write` + `memories:read` grant). No image, tailnet or Vercel
  deployment has been exercised.
- The desktop app remains a preview: macOS DMGs only, ad-hoc signed without notarization, no
  Linux or Windows package. Local identities are cooperation conventions between trusted
  processes, not authenticated identities.

## Install

Same channels as v0.1.0 — `brew install --cask LennardZuendorf/tap/shards` for the app with
both tools, `brew install LennardZuendorf/tap/shards-cli` for CLI and MCP only. macOS needs
13.3 or later; the standalone Linux tools need x86_64 and glibc 2.35+. If macOS blocks the
first launch, use **System Settings → Privacy & Security → Open Anyway** only when you trust
the source and have verified the download.

| Platform | Desktop + bundled tools | CLI + MCP |
|---|---|---|
| Mac, Apple Silicon | `Shards-0.2.0-aarch64-apple-darwin.dmg` | `shards-cli-0.2.0-aarch64-apple-darwin.tar.gz` |
| Mac, Intel | `Shards-0.2.0-x86_64-apple-darwin.dmg` | `shards-cli-0.2.0-x86_64-apple-darwin.tar.gz` |
| Linux, x86_64, glibc 2.35+ | — | `shards-cli-0.2.0-x86_64-unknown-linux-gnu.tar.gz` |
